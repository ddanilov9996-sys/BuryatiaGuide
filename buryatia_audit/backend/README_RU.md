# BuryatiaGuide API — v4.1 scaffold

Серверная основа без сторонних npm-зависимостей (Node.js 20+). Это локальный/тестовый каркас, не готовый публичный продакшен.

## Запуск локально
1. Установить Node.js 20 или новее.
2. В папке `backend` скопировать `.env.example` в `.env`, задать уникальный `ADMIN_TOKEN`.
3. В терминале из `backend` выполнить `npm start` (или `node server.mjs`).
4. Проверить `http://127.0.0.1:3000/api/health` и `/api/organizations`.

Переменные окружения нужно экспортировать перед запуском. `.env` не читается автоматически без стороннего пакета:

```bash
export HOST=127.0.0.1
export PORT=3000
export ADMIN_TOKEN='replace-with-a-long-random-secret'
export DATA_DIR='./data'
node server.mjs
```

## API
- `GET /api/health` — health check.
- `GET /api/organizations` — публичный JSON текущего каталога.
- `POST /api/admin/organizations` — заменить каталог; заголовок `Authorization: Bearer <ADMIN_TOKEN>`, тело JSON с массивом `organizations` или массивом записей.

Каждая запись должна иметь `name`, `district`, `category`, `source` (HTTPS), `checkedAt` (`YYYY-MM-DD`). Поддерживаемые статусы: `verified`, `needs_review`, `unverified`, `source_only`. Сервер не объявляет запись подтверждённой только из-за наличия source; статус передаёт администратор.

## Пример обновления базы
```bash
curl -X POST http://127.0.0.1:3000/api/admin/organizations \
  -H 'Authorization: Bearer YOUR_ADMIN_TOKEN' \
  -H 'Content-Type: application/json' \
  --data-binary @organizations.json
```

## Важные ограничения
- Синхронизация с внешними источниками **не реализована**. Нужны отдельные проверенные адаптеры под конкретные российские API/реестры, их лицензии и ключи доступа.
- API не подключён к публичному интернету; публичное размещение требует HTTPS reverse proxy, firewall, rate limiting, резервного копирования, мониторинга, управления секретами, обновлений Node.js и аудита безопасности.
- Не содержит пользовательских аккаунтов, отзывов, персональных данных или геолокационных логов.
- Файл JSON — временное хранилище для прототипа, не замена полноценной БД на продакшене.
- Не юридическая сертификация. Перед публикацией провести правовую и техническую проверку.

## Панель администратора (v4.2)
После запуска откройте `http://127.0.0.1:3000/admin`. Введите `ADMIN_TOKEN`, загрузите текущий каталог или выберите JSON-файл, проверьте содержимое и сохраните. Сохранение заменяет весь каталог целиком; перед операцией панель показывает подтверждение. Токен не сохраняется в localStorage/sessionStorage и действует только пока открыта вкладка.

Панель — инструмент оператора, а не публичная форма добавления организаций. Не размещайте её в интернете до настройки HTTPS, ограничений доступа к `/admin`, резервного копирования и защиты сервера. Текущая версия всё ещё использует JSON-файл как временное хранилище.
